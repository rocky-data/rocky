The UI is off. `rocky serve --ui` and `--allowed-host` shipped after
engine-v1.73.0, which is this chart's appVersion. Raise image.tag to a release
that carries them, then set serve.ui.enabled=true.

1. Put a project on the volume. The chart does not deliver one.

   The image mounts it at /data, so /data/rocky.toml and /data/models/ must
   exist. The state store is written to /data/models/.rocky-state.redb and the
   scheduler's files to /data/.rocky/.

     kubectl cp ./my-project \
       "$(kubectl get pod -l app.kubernetes.io/instance=rocky-acc -o name | cut -d/ -f2):/data"

   Or set initContainers to clone it from your repository.

2. Reach it.

     kubectl port-forward svc/rocky-acc 8080:8080
     # http://localhost:8080/

3. The token is in the Secret you named, rocky-serve, under
   the key token. This chart never printed it and
   never held it.

     kubectl get secret rocky-serve -o jsonpath='{.data.token}' | base64 -d

Two things to know before you rely on this:

  - /api/v1/health, which both probes use, is shallow. It answers as soon as
    the listener is bound. It does not prove the project compiled or that the
    scheduler is running.

  - This chart is community-supported, like the Compose example in
    deploy/rocky/. It encodes the deployment contract; it is not a supported
    deployment.
