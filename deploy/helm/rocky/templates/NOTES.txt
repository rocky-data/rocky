Rocky is installed as {{ include "rocky.fullname" . }}.

  image      {{ include "rocky.image" . }}
  volume     {{ include "rocky.claimName" . }} ({{ .Values.persistence.accessMode }}, class {{ .Values.persistence.storageClassName | default "<existing claim>" }})
  scheduler  {{ .Values.scheduling.mode }}
  browser UI {{ if .Values.serve.ui.enabled }}on, token scope {{ .Values.serve.ui.tokenScope }}{{ else }}off{{ end }}

{{ if not .Values.serve.ui.enabled -}}
The UI is off: the API answers, the page does not. Set serve.ui.enabled=true
for the page; this chart's appVersion carries it.
{{- end }}

1. Put a project on the volume. The chart does not deliver one.

   The image mounts it at /data, so /data/rocky.toml and /data/models/ must
   exist. The state store is written to /data/models/.rocky-state.redb and the
   scheduler's files to /data/.rocky/.

   `kubectl cp` straight into the Rocky pod does not work: the image is
   distroless and has no tar. Copy through a throwaway pod that mounts the
   same claim, then chown the tree to 65532 — the steps are in
   docs/guides/kubernetes/ under "Put your project on the volume". Or set
   initContainers to clone it from your repository.

2. Reach it.

{{- if .Values.ingress.enabled }}

     http{{ if .Values.ingress.tls }}s{{ end }}://{{ .Values.ingress.host }}{{ .Values.ingress.path }}{{ if .Values.serve.ui.enabled }}ui/{{ end }}

   Only that host works. The server is started with --allowed-host
   {{ .Values.ingress.host }}, and a request carrying any other Host is
   refused 421.
{{- else }}

     kubectl port-forward svc/{{ include "rocky.fullname" . }} 8080:{{ .Values.service.port }}
     # http://localhost:8080/{{ if .Values.serve.ui.enabled }}ui/{{ end }}
{{- end }}

3. The token is in the Secret you named, {{ .Values.existingSecret.name }}, under
   the key {{ .Values.existingSecret.tokenKey }}. This chart never printed it and
   never held it.

     kubectl get secret {{ .Values.existingSecret.name }} -o jsonpath='{.data.{{ .Values.existingSecret.tokenKey }}}' | base64 -d

Three things to know before you rely on this:

{{- if not .Values.persistence.existingClaim }}

  - The claim {{ include "rocky.claimName" . }} is annotated
    helm.sh/resource-policy: keep. `helm uninstall` leaves it behind, so your
    project and its run history survive. Installing again under this release
    name ADOPTS that same claim, with whatever was already on it. To start
    clean, delete the claim yourself.
{{- end }}

  - /api/v1/health, which both probes use, is shallow. It answers as soon as
    the listener is bound. It does not prove the project compiled or that the
    scheduler is running.

  - This chart is community-supported, like the Compose example in
    deploy/rocky/. It encodes the deployment contract; it is not a supported
    deployment.
