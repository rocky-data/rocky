# rocky-vscode — Agent Instructions

VS Code extension for the Rocky SQL transformation engine. LSP client that communicates with `rocky lsp` over stdio, plus commands for AI features, diagnostics, and operational tasks.

**Local skill:** `editors/vscode/.agents/skills/tailwind-plus-elements/` (mirrored in `.claude/skills/`) covers `@tailwindplus/elements` web components in the React webviews under `webview-ui/`. Read its `SKILL.md` before building or upgrading an interactive webview surface.

## Architecture

```
Extension (TypeScript)  ──stdio JSON-RPC──▶  rocky lsp (Rust binary)
```

The extension is an LSP client. All language intelligence (diagnostics, completion, hover, go-to-definition, rename, etc.) comes from the Rocky CLI's built-in LSP server. The extension handles:
- LSP client lifecycle (start/stop/restart) plus an `LspState` lifecycle emitter consumed by sidebar views
- Status bar with server state + error count
- Commands grouped by concern, one file per concern under `src/commands/` (run `ls src/commands`), plus the `commandPalette` entry point and inline code-lens commands
- Code lens (inline run/compile above models)
- Activity bar sidebar views (Get Started, Extension Info, Models, Runs, Sources, Schema, Previews, Branches, Help) — empty-state copy is gated on the `rocky.hasProject` context flag so a workspace without a `rocky.toml` shows orientation instead of CLI errors
- Rocky Inspector (bottom-panel React webview under `webview-ui/`): per-model trust dashboard + interactive lineage canvas (`@xyflow/react` + `@dagrejs/dagre` layout)
- Legacy plain-HTML webviews (run summary, doctor) — `src/webviews/`
- Test explorer integration
- Drift diagnostics, formatting, folding providers

## Coding Standards

### TypeScript
- Target: ES2022, Module: CommonJS
- Strict mode enabled
- VS Code API minimum: 1.120.0 (must match the version pinned in `src/test/runTest.ts`; test runner activates against that exact build)
- Use `cp.execFile()` for subprocess calls (not `cp.exec()` — no shell injection)
- Use `vscode.window.withProgress()` for long-running commands
- Escape HTML in webview content via `escapeHtml()`

### Dependencies
- Runtime: `vscode-languageclient`. Dev: `typescript`, `@vscode/vsce`, `mocha`, `vitest`.
- Versions live in `package.json`. Read it before you quote one.

## Extension Commands

`package.json` (`contributes.commands`) is the only list of commands. It holds about 60. This file does not copy them. To see them all:

```bash
node -e 'for (const c of require("./package.json").contributes.commands) console.log(c.command, "—", c.title)'
```

To add a command: implement it in the matching `src/commands/<concern>.ts`, register it in `src/commands/index.ts`, and add its `contributes.commands` entry (plus any `menus` entry) to `package.json`.

## Configuration Settings

Generated from `package.json` (`contributes.configuration`), which wins if the two differ.

| Setting | Default | Purpose |
|---------|---------|---------|
| `rocky.server.path` | `"rocky"` | Path to the Rocky binary |
| `rocky.server.extraArgs` | `[]` | Extra arguments to pass to rocky lsp |
| `rocky.inlayHints.enabled` | `true` | Show inferred types inline |
| `rocky.statusBar.segments` | `[]` | Optional status bar segments to show after the LSP state |
| `rocky.diagnostics.enabled` | `true` | Enable drift diagnostics (inline errors/warnings from `rocky compile`) |
| `rocky.costAnnotations.enabled` | `true` | Show inline cost annotations (CodeLens) above model files |
| `rocky.preview.rowLimit` | `100` | Maximum rows returned by **Rocky: Preview** (`rocky preview rows --limit`) |
| `rocky.preview.allowWarehouse` | `false` | Allow row previews to execute against a non-DuckDB warehouse (Databricks/Snowflake/BigQuery/Trino) |
